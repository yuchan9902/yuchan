# FitLog — 운동 기록 & 통계

세트별 무게·횟수를 기록하면 볼륨, 부위별 분포, 추정 1RM 추이, 운동 달력을 자동으로 계산해 주는
웹앱입니다. 데이터는 브라우저 `localStorage`에만 저장되고 서버로 나가지 않습니다.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 로 정적 빌드
npm run preview
```

빌드 결과는 순수 정적 파일이라 GitHub Pages·Netlify·S3 어디에나 그대로 올릴 수 있습니다
(`vite.config.ts`의 `base: './'` 덕분에 하위 경로 배포도 동작합니다).

## 배포

`.github/workflows/deploy.yml`이 배포를 담당합니다.

- **PR**: `npm ci → lint → build`만 돌려서 빌드가 깨지지 않았는지 확인합니다.
- **main 푸시**: 같은 빌드를 돌린 뒤 `dist/`를 GitHub Pages에 게시합니다.
- 수동 실행이 필요하면 Actions 탭에서 workflow_dispatch로 돌릴 수 있습니다.

**처음 한 번은 저장소 설정이 필요합니다** — Settings → Pages → Build and deployment →
Source를 **GitHub Actions**로 바꿔주세요. 그 다음부터 main에 머지될 때마다
`https://<사용자명>.github.io/<저장소명>/` 으로 자동 배포됩니다.

다른 곳에 올릴 때도 빌드 명령은 같습니다.

| 호스트 | 설정 |
|---|---|
| Netlify | base `workout-tracker`, build `npm run build`, publish `workout-tracker/dist` |
| Vercel | root directory `workout-tracker` (Vite 프리셋 자동 인식) |
| S3 · 정적 서버 | `workout-tracker/dist`를 통째로 업로드 |

클라이언트 라우터가 없어서(탭 상태만 사용) SPA 404 폴백 설정은 필요 없습니다.

## 화면

| 탭 | 내용 |
|---|---|
| **대시보드** | 총 볼륨(히어로 수치)·운동한 날·총 세트·유산소·연속 기록 타일, 주별 볼륨 누적 막대, 부위별 분포, 최근 기록 |
| **기록** | 날짜·종목·세트(무게 × 횟수) 입력, 유산소는 시간·거리로 입력, 기록 수정·삭제, 사용자 종목 추가 |
| **통계** | 종목별 추정 1RM 추이(크로스헤어 라인), 운동 달력 히트맵, 종목별 개인 기록(PR) 표 |

기간 필터(최근 7일 / 30일 / 90일 / 6개월 / 전체)는 화면 위 한 줄에만 존재하고, 그 아래 모든 카드가
같은 구간으로 다시 계산됩니다. 헤더의 아이콘으로 JSON 백업 내보내기·불러오기, 예시 데이터 초기화를
할 수 있습니다.

### 계산 방식

- **볼륨(tonnage)** = Σ (무게 × 횟수). 맨몸 세트는 0kg이지만 세트 수에는 포함됩니다.
- **추정 1RM** = Epley 공식 `무게 × (1 + 횟수 / 30)`. 12회를 넘는 세트는 추정 오차가 커서 제외합니다.
- **연속 기록**은 오늘(또는 어제)부터 거꾸로 세어, 기록이 하루라도 비면 끊깁니다.
- **증감률**은 같은 길이의 직전 구간과 비교한 값입니다.

첫 실행 시에는 약 6개월치 예시 데이터(5분할 루틴 + 점진적 과부하)가 채워집니다. 헤더의 초기화
버튼으로 언제든 되돌릴 수 있고, 실제 기록을 시작하려면 예시 기록을 지우고 쓰면 됩니다.

## 디자인 시스템

[React Native Reusables](https://reactnativereusables.com/)의 테마를 그대로 가져왔습니다.
`src/index.css`의 중립 스케일·반경·컴포넌트 토큰(`--background`, `--foreground`, `--card`,
`--primary`, `--muted`, `--border`, `--ring`, `--radius: 0.625rem` …)은 RNR의 라이트/다크 값
그대로이고, 버튼·카드·뱃지·인풋·셀렉트·탭·테이블도 같은 규격(`h-9`, `rounded-md`, `rounded-xl`,
`shadow-sm`, `focus-visible:ring-[3px]`)으로 맞췄습니다. RNR은 React Native용 라이브러리라서
컴포넌트 코드를 그대로 쓸 수는 없고, 동일한 토큰과 형태로 웹(React + Tailwind v4)에 옮겼습니다.

### 차트 색상만 예외

RNR 기본 `--chart-1..5`는 계열 색 검사를 통과하지 못합니다. 라이트 모드 값(`#e76e50`, `#2a9d90`,
`#274754`, `#e8c468`, `#f4a462`)을 검증기에 돌리면 인접 쌍 `#f4a462 ↔ #e8c468`의 색각 이상 ΔE가
4.7, 정상 시야 ΔE도 7.9로 하한(15)에 한참 못 미치고, `#274754`는 채도 하한에도 걸립니다. 부위가
7개라 다섯 칸으로는 모자라기도 합니다.

그래서 계열 색만 검증을 통과한 7색 팔레트로 교체했습니다 (라이트 기준 인접 쌍 색각 ΔE 9.1, 정상
시야 ΔE 19.6 — 두 모드 모두 전 항목 통과):

| 슬롯 | 부위 | 라이트 | 다크 |
|---|---|---|---|
| 1 | 가슴 | `#2a78d6` | `#3987e5` |
| 2 | 등 | `#eb6834` | `#d95926` |
| 3 | 하체 | `#1baf7a` | `#199e70` |
| 4 | 어깨 | `#eda100` | `#c98500` |
| 5 | 팔 | `#e87ba4` | `#d55181` |
| 6 | 코어 | `#008300` | `#008300` |
| 7 | 유산소 | `#4a3aa7` | `#9085e9` |

색은 순위가 아니라 **부위에 붙습니다** — 필터를 바꿔 계열이 줄어도 남은 부위의 색은 그대로입니다.
슬롯 순서 자체가 색각 안전 장치라서 임의로 바꾸면 안 됩니다. 히트맵은 계열색이 아니라 파랑 한 색의
명도 램프를 쓰고, 다크 모드에서는 어두운 쪽이 "적음"이 되도록 방향을 뒤집습니다.

라이트 모드에서 하체·어깨·팔 세 색은 흰 배경 대비가 3:1 아래라, 그 차트들은 **모든 값에 직접
라벨을 붙이거나 표 보기를 제공**해 색만으로 값을 읽게 하지 않습니다. 차트 카드 오른쪽 위 토글로
언제든 같은 데이터를 표로 볼 수 있고, 툴팁은 어디까지나 보조 수단입니다. 계열이 둘 이상이면 범례가
항상 표시되고, 막대·점·셀은 키보드 포커스로도 툴팁과 같은 내용을 읽을 수 있습니다.

## 구조

```
src/
  lib/        types · catalog(기본 종목) · seed(예시 데이터) · store(localStorage) · stats(집계) · range · utils
  components/
    ui/       RNR 규격 프리미티브 (button, card, badge, input, tabs, table)
    charts/   primitives(측정·툴팁·범례·눈금) + 주별 볼륨 · 부위별 막대 · 1RM 라인 · 활동 히트맵
    …         StatTile · ChartCard(차트/표 토글) · FilterBar · ThemeToggle
  views/      Dashboard · LogView · StatsView
```

차트는 외부 차트 라이브러리 없이 SVG로 직접 그립니다. 컨테이너 폭을 `ResizeObserver`로 재서 실제
픽셀 크기로 렌더링하므로 `viewBox` 확대·축소로 글자가 늘어나지 않습니다.
